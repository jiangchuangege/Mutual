# 游戏导入 & 双人联机接口

这套东西解决一件事：**从别的地方下载的游戏（itch.io、网页小游戏、AI 生成的单文件 HTML），
直接传进游戏库，并且能两个人一起玩**，而且不需要改游戏本身。

---

## 一、怎么导入

| 方式 | 具体做法 | 适合 |
|---|---|---|
| 电脑网页 | 浏览器打开 `https://<你的服务器地址>/import`（内网就是 `http://<服务器IP>:8787/import`）→ 填账号 + 6 位登录码 → 把 `.html` 拖进去 | **下载游戏在电脑上**的场景，最省事 |
| 选文件 | 游戏库 → 「📁 导入下载来的游戏」→ 选 `.html`/`.htm`/`.apk` | 文件已经在手机上 |
| 粘贴代码 | 游戏库 → 「＋ 粘贴 AI 写的游戏代码」→ 贴整段 HTML | AI 直接给你的代码 |
| 云编译 | 粘贴 Java/原生源码 → 「云编译成原生 APK」 | 安卓原生游戏 |

导入后：

1. 文件传到服务器（`/api/upload`，上限约 95MB），返回一个 `/game/xxx.html` 地址；
2. 库里只存这个地址（`assetPath`），两台手机都能下载 → **两边跑的是同一个文件**；
3. 第一次点开下载到手机私有目录，之后离线也能玩。

> `.zip` 不行：请先解压，把里面的 `index.html` 传进来（zip 里的相对路径图片/音频会丢，
> 单文件游戏才是这套的目标形态）。

### 什么能用、什么不能用（先看这张表，少走弯路）

| 下载来的文件 | 能不能在游戏库里打开 | 能不能双人 |
|---|---|---|
| 单文件 `.html`（网页游戏） | ✅ 直接开，WebView 里跑 | ✅ 自动镜像操作 + 同种子随机 |
| `.apk`（安卓安装包） | ✅ 点卡片 → 装一次 → **之后再点就打开这个游戏** | ❌ 独立原生 App，注入不进去 |
| PC / Mac 版（`.exe` / `.app` / `.sh` / `.py` / 电脑 zip） | ❌ 手机上没有对应的运行环境 | ❌ |
| Rust/Ren'Py/Unity 的电脑版 | ❌ 同上（除非作者另外提供了网页版） | ❌ |

**APK 是怎么"从库里打开"的**：服务端在导入时解析 APK 里的 `AndroidManifest.xml`（二进制 AXML），
把包名（如 `com.demo.game`）记进这条游戏记录 —— 手机点卡片时先按包名拉起来，拉不起来才弹安装器。
以前这里写死了我们云编译的 `com.mutual.generated`，所以别人的 APK 装上却打不开。

## 二、双人怎么玩（零改动，自动生效）

导入的游戏完全不知道自己被套了一层联机层，但两台手机会：

```
手机 A：玩家 A 按键 ──┐                                  ┌── 合成同样的按键 ──> 游戏认为玩家A按的
                      ├─ TW_NET 小包 ─> 服务器 ─> 对方 ─┤
手机 B：玩家 B 按键 ──┘                                  └── 合成同样的按键 ──> 游戏认为玩家B按的
```

具体三件事（代码在 `src/core/gameNet.ts`）：

1. **输入镜像**：键盘/指针/触摸事件压成一行 `类型|键|x|y`（坐标归一化到 0~1，屏幕大小不同也能对上），
   每 60ms 打包一次发给对方，对方在自己的页面里合成同样的事件（`KeyboardEvent` / `PointerEvent`）。
2. **同种子随机**：`Math.random` 被替换成一颗共享种子的线性同余发生器
   （种子 = `seedOf(空间id + 游戏id)`，两台手机算出来一样）→ 怪物、掉落、洗牌顺序完全一致。
3. **顺序**：联机层在游戏脚本**之前**注入，保证游戏初始化用到的随机数已经是共享序列。

**两个人怎么分工**（下载来的游戏本来就是"一台电脑两个人玩"）：

- 一个用方向键 / 空格，另一个用 `WASD` / 另一边屏幕 —— 各按各的，互不干扰；
- 手机横屏一人一半也能玩（触摸坐标是归一化的）；
- 只支持单人的游戏也一样能"一起看、轮流按"，两边画面完全一致。

### 已知边界（老实说）

- 输入是**尽力同步**：没有帧级回滚（rollback），网络抖动大时两边动作顺序可能差一帧；
  连续控制类游戏（跑跳、弹球、射击）没问题，**严格回合制**建议用下面的 `TwNet.state`。
- 用 `setInterval` + 真实时间做逻辑的游戏，两台手机时钟不同会有细微差；
  需要绝对一致的游戏请用 `TwNet.state` 整段同步。

## 三、给游戏作者的可选接口（写了更稳）

任何游戏（包括下载来的，自己改一行也行）可以在页面里用这些 API：

```js
// 1. 我是谁 / 对方在不在
TwNet.role        // 'A' | 'B'
TwNet.connected   // 最近 6 秒收到过对方包 → true

// 2. 自定义动作（推荐：只发"操作"，不发整个世界）
TwNet.send({ move: [12, 30] })
TwNet.onAction(function (data) { /* 对方操作到了 */ })

// 3. 整段局面（严格回合制用这个）
TwNet.state({ board: ['x','o',''] })            // 对象或 JSON 字符串都行
TwNet.onState(function (json) { /* 恢复局面并重绘 */ })

// 4. 调试
TwNet.packets     // 收到过多少包
TwNet.latency()   // 距上次收包多少毫秒（-1 = 从没收到）
```

老接口 `TwGame.send / TwGame.apply`（整段局面同步）**继续可用**，两者互不覆盖：
`TwGame` 走 `TW_STATE:`，联机层走 `TW_NET:`。

### 顺便：游戏可以声明自己叫什么

在 HTML 里加一行注释，导入时游戏库就用这个名字，而不是文件名：

```html
<!--mutual-game {"title":"像素农场","players":2,"controls":"A:WASD B:方向键"}-->
```

## 四、数据是怎么走的（安全边界）

```
WebView（游戏页面）
   │  window.ReactNativeWebView.postMessage('TW_NET:' + 包)
   ▼
GamePlayer（React Native）
   │  onState('@n:' + 包) → store.pushGameState → hub.pushGameState
   ▼
服务器（零依赖 Node）
   │  只存字符串、广播给同一对的那台手机，从不 eval 陌生代码
   ▼
对方 GamePlayer → TwNet.applyRemote(包) → 合成事件
```

- 一个输入包典型 30~120 字节，一局游戏的包总量远小于一张图片；
- 服务端对包做了长度/条数上限（一包最多 200 条操作、局面最多 2MB），坏包一律丢弃不抛错；
- 联机层只在游戏自己的 WebView 里跑，碰不到 App 的 JS 上下文，也拿不到账号 token。

## 五、代码位置

| 文件 | 作用 |
|---|---|
| `src/core/gameNet.ts` | 联机层本体：种子随机、输入采集/回放、包编解码、清单解析 |
| `src/core/gameRuntime.ts` | 把联机层注入到完整 HTML / 片段页面里（`buildRuntimeHtml(code, net)`） |
| `src/app/games.tsx` | 注入时机、`TW_NET` / `TW_STATE` 分流、导入入口 |
| `src/store.tsx` | `uploadGameFile()`（带 title）、`pushGameState()` |
| `tests/gameNet.test.js` | 纯逻辑测试（种子一致性、坏包、注入顺序…） |
| `tools/net-demo.cjs` | 浏览器里两个 iframe 的性能验证（输入镜像 + 同步一致性） |
